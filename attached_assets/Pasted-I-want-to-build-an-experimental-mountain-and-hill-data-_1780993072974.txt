I want to build an experimental mountain and hill data verification system to test whether we can replace GPT-generated elevation data with real geographic calculations.

IMPORTANT:
Do NOT modify the existing mountain lookup system.
Do NOT remove any current functionality.
This must be a completely separate test feature.

GOAL

I want to enter any hill or mountain name and compare:

1. Current GPT-generated route data
2. Calculated route data from real geographic sources

The purpose is to determine whether we can reliably calculate:

* Elevation gain
* Distance
* Summit elevation
* Trailhead elevation
* Gradient

using real terrain and route data.

---

## PHASE 1 - TEST ENDPOINT

Create:

POST /api/mountain-verification-test

Input:

{
"mountainName": "Musbury Tor"
}

---

## PHASE 2 - FIND MOUNTAIN

Use a geocoding service such as:

* OpenStreetMap Nominatim
* GeoNames

to retrieve:

* Name
* Latitude
* Longitude
* Summit elevation (if available)

Store all returned data.

---

## PHASE 3 - FIND ROUTES

Use OpenStreetMap / Overpass API to search for:

* hiking routes
* footpaths
* mountain paths
* bridleways
* public rights of way

within a reasonable radius of the summit.

Attempt to identify likely hiking approaches.

Return up to 5 candidate routes.

---

## PHASE 4 - ROUTE GEOMETRY

For each candidate route:

Retrieve route geometry as coordinate arrays.

Store:

* route name
* route coordinates
* route length

---

## PHASE 5 - ELEVATION PROFILE

For every route:

Sample points every 10-20 metres along the route.

Retrieve elevation using a real DEM source:

Preferred:

* Copernicus DEM
* OpenTopoData
* Open Elevation
* SRTM

Generate:

* elevation profile
* highest point
* lowest point
* trailhead elevation

---

## PHASE 6 - TRUE ELEVATION GAIN

DO NOT calculate:

elevation gain = summit - trailhead

Instead:

1. Walk through all sampled elevations.
2. Sum only positive elevation changes.
3. Ignore fluctuations under 3 metres.
4. Return:

totalElevationGain

This should mimic Garmin / Strava / AllTrails calculations.

---

## PHASE 7 - ROUTE METRICS

Calculate:

* distanceKm
* totalElevationGain
* summitElevation
* trailheadElevation
* averageGradient
* maximumGradient

---

## PHASE 8 - CONFIDENCE SCORE

Generate:

HIGH

* verified elevation profile

MEDIUM

LOW

## SUCCESS CRITERIA

The experiment is successful if:

1. Calculated route data can be generated without GPT.
2. Elevation gain is calculated from terrain profiles rather than summit minus trailhead.
3. Results are within approximately 10% of known hiking route data.
4. We can evaluate whether this approach should replace the current GPT-generated mountain metrics.

Before making any production changes, provide a report showing:

* Data sources used
* Accuracy observed
* Estimated API costs
* Estimated performance impact
* Recommended next steps
