Build Priority 1 for Summit Ready.

Priority 1 = user-powered hill data verification.

Goal:
When a training plan includes a hill session, the session should clearly show the planned hill details and allow the user to either:

1. Mark the session complete using the estimated plan data, or
2. Track the hike live so the recorded GPS/elevation data can improve our hill database.

Do not remove current functionality.
Do not break the current training plan screen.
Build this as an enhancement to the existing hill repeat session card.

## DATA RULES

Manual completions:

completionType = "estimated_manual"

These count towards the user's plan progress.

They must NOT update verified hill data.

Tracked completions:

completionType = "tracked_gps"

These count towards plan progress.

They may be used for route verification only if quality checks pass.

---

## QUALITY CHECKS

Create a data_quality_score from 0-100.

A tracked hike can be used for verification only if:

* data_quality_score >= 75
* match_confidence >= 80
* GPS track is long enough
* duration is sensible
* average speed is realistic for hiking
* no major GPS jumps
* elevation gain is not a major outlier
* route appears to match the planned hill

If data is poor, save the hike to the user's history but set:

used_for_verification = false

---

## VERIFICATION LOGIC

When at least 3 good tracked hikes exist for a hill/route:

Update:

* verified_elevation_gain_m
* verified_distance_km
* verified_sample_count
* confidence_score = "MEDIUM"

Use median values, not just averages.

When at least 10 good tracked hikes exist:

confidence_score = "HIGH"

In the app display:

If verified data exists:

"Verified gain: 247m, based on 6 tracked hikes"

If not:

"Estimated gain: 220m. Track this hike to improve accuracy."

---

## CANONICAL HILL MATCHING

When saving a hill session, try to match the hill to an existing canonical_hills record.

Match using:

1. Similar name
2. Alternative names
3. Coordinates if available
4. Summit elevation similarity
5. Region/country

Avoid duplicate records where possible.

Examples:

* Snowdon and Yr Wyddfa should eventually resolve to the same canonical hill.
* Peel Tower and Holcombe Hill should be linked carefully if referring to the same climb area.

If unsure, create a new hill record but mark confidence_score = "LOW".

## SUCCESS CRITERIA

This feature is successful if:

1. Hill sessions display hill name, summit height, estimated gain, target reps and estimated total gain.
2. User can mark hill session complete using estimated data.
3. User can track the hike from the session card.
4. Tracked hike is saved against the correct training session.
5. Tracked hike is linked to a canonical hill record.
6. Manual completions count for user progress but do not verify hill data.
7. GPS-tracked completions can improve verified hill statistics.
8. Bad GPS data is rejected from verification.
9. Admin can review, approve, reject and merge hill data.
10. Existing training plan and tracking functionality still works.
