# Canonical activity contracts

S2-C02 centralizes the conventions future Training, Expedition, Free Hike, and provider adapters must use. The implementation is in:

- `artifacts/api-server/src/services/canonicalActivityContracts.ts`

## Source identities

Persist source identity as the existing two-column pair:

- `source_type`
- `source_id`

Built-in namespaces:

- `tracked_hill_session`
- `training_manual`
- `explore_hike`

External namespaces:

- `provider:<provider>`
- `import:<provider>`

Existing Phase 1 values remain valid as legacy namespaces. In particular, the tracked-hill bridge continues to persist:

- `source_type = tracked_hill_session`
- `source_id = <existing client activityId>`

Do not replace that pair with a colon-concatenated database value. `canonicalSourceIdentityKey()` is only a deterministic encoded key for comparisons, logs, and tests.

Source IDs must be stable IDs generated by their source. Never derive them from names, dates, distance, elevation, or other mutable activity facts.

## Link targets

Existing non-namespaced link IDs remain valid.

Summit Data Engine references use:

- mountain: `sde:mountain:<mountains.id UUID>`
- route: `sde:route:<encoded route identity key>@<encoded version>`

SDE mountain targets use the existing `canonical_hill` link type. SDE route targets use `canonical_route`. These are service-layer conventions and do not change the Phase 1 persisted link schema.

Do not use summit names, slugs, app serial IDs, or spreadsheet IDs as cross-catalogue identity.

## Evidence classifications

| Classification | Existing evidence storage | Initial evidence state | Marker |
|---|---|---|---|
| `gps_recorded` | `gps_track`, `elevation_profile`, optional `source_snapshot` | `recorded_unverified` | Not required |
| `estimated_manual` | `manual_estimate`, optional `source_snapshot` | `unverified_manual` | Not required |
| `indoor_training` | `source_snapshot` | `unverified_manual` | Required |
| `unavailable_untrusted` | `source_snapshot` | `unverified_manual` | Required |

The marker is the classification stored in the source snapshot/payload by future adapters. This preserves meaning without adding an unsupported evidence type or changing the database schema.

Evidence classification does not itself grant readiness, Elevation Bank, summit, challenge, or competitive eligibility. Those decisions belong to versioned qualifications.

## Adapter boundary

Future source adapters implement `CanonicalActivityAdapter<TInput>` and return `CanonicalActivityAdapterOutput`.

Adapters:

- generate or preserve stable source identity;
- map source metrics and private evidence without changing their meaning;
- attach independent product links;
- do not accept or derive ownership.

The authenticated API route attaches the verified Clerk owner before canonical ingestion. One adapter output represents one physical activity; additional Training, Expedition, hill, route, or challenge purposes are links rather than copied activities.
